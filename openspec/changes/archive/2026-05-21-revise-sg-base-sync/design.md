## Context

README.md 已更新为沙箱技能统一使用 `sg-*` 前缀（6 个技能），且明确声明"支持纯本地使用，无需远程仓库"。现有 `sandgit-base-sync` 技能命名与 README 不符，且执行逻辑以远程同步为默认路径，与"本地优先"定位冲突。

## Goals / Non-Goals

**Goals:**
- 技能文件夹及所有元数据从 `sandgit-base-sync` 重命名为 `sg-base-sync`
- 执行逻辑改为"本地优先"：默认直接切换到 main，远程同步作为用户可选步骤
- 非 main 分支切换策略智能化：已提交 → 直接切；未提交 → 询问保存（commit）后切

**Non-Goals:**
- 不修改其他 5 个技能（本次仅处理 sg-base-sync）
- 不改变沙箱分支的创建/合并策略

## Decisions

1. **远程同步改为可选询问**：检测到远程仓库后，用 AskUserQuestion 询问用户"是否同步远程"，而非自动拉取。
   - 理由：README 明确本地优先，远程同步不应成为默认行为。大部分本地使用场景不需要联网。

2. **未提交变更处理改用 commit 而非 stash**：当用户有未提交变更时，询问是否 `git add -A && git commit` 保存，而非自动 stash。
   - 理由：stash 容易忘记恢复，commit 保留在分支历史上更安全、更可追溯。且与 sandgit 沙箱理念一致——沙箱内自由开发，分支就是用来暂存工作进度的。
   - 替代方案（stash）：更轻量但容易丢，不符合"沙箱分支随便折腾"的理念。

3. **已提交变更直接切分支**：若当前分支已全部提交，工作目录干净，直接 `git checkout main`，无需询问。
   - 理由：已提交的内容安全保存在分支上，切换无风险。

## Risks / Trade-offs

- **风险**：用户可能不希望自动 commit 混杂文件 → **缓解**：commit 前展示变更列表，用户确认后再执行
- **权衡**：commit 会产生一个新的提交记录 vs stash 不产生记录 → 沙箱分支本就是临时分支，产生记录无负面影响，且 commit 更安全
