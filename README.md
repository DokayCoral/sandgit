# sandGit
轻量 Git 沙箱开发规范，专为 AI 辅助编程设计
（支持纯本地使用，无需远程仓库）

## 核心理念
利用 Git 原生分支隔离能力，实现极简代码沙箱。
沙箱内自由开发调试，合并前严格校验，未审核、未通过测试的代码绝不进入 main 主干，兼顾灵活性与安全性。

## 沙箱划分
- 正式主干：`main`（唯一稳定分支，禁止直接修改）
- 测试沙箱：`sgtest/*` 分支，编写/确认测试框架
- 业务沙箱：`sgcode/*` 分支，开发业务逻辑

## 🔥 权限规则（灵活 + 安全）
1. **沙箱内部：权限全开**
   临时分支内可自由修改任何文件，支持调试、试错，不受限制
2. **合并主干：严格校验**
   - 测试沙箱：仅允许合并测试代码
   - 业务沙箱：必须通过全部测试，且禁止修改测试文件
3. **废弃沙箱：一键删除**
   开发失败直接丢弃，不留下任何脏代码

## 执行原则
1. 先建测试沙箱，人工确认测试思路后入库
2. 测试标准固定后，再开启业务沙箱
3. 业务代码必须通过全部测试
4. 沙箱失败/废弃直接删除，不污染主干

## 配套 Claude 技能（6个，统一前缀）
- sg-base-sync        同步主干基线，清理本地环境
- sg-test-branch-run  创建测试沙箱 + 编写测试 + 人工审核
- sg-test-finalize    测试合并到 main + 删除测试沙箱
- sg-code-branch-run  创建业务沙箱 + 开发代码 + 测试校验
- sg-code-finalize    业务合并到 main + 删除业务沙箱
- sg-branch-abort     一键废弃沙箱，回退干净主干

## 标准开发流程
1. 同步最新 main 代码
2. 测试沙箱开发（自由调试）→ 审核通过
3. 合并测试 → 销毁测试沙箱
4. 再次同步 main
5. 业务沙箱开发（自由调试）→ 全量测试通过 → 审核通过
6. 合并业务 → 销毁业务沙箱

## 异常处理
- 测试不合格：沙箱内修改或直接废弃
- 业务不通过测试：只改业务，不改测试
- 需求变更：丢弃沙箱，重新开始
- 暂停开发：保留分支，后续继续

## 🔥 重要：无远程仓库 / 纯本地使用
本工具 **完全支持本地单机 Git**，不需要 GitHub、不需要联网、不需要远程仓库。
所有分支、合并、沙箱、安全机制，均在本地完成，流程完全不变。

## 核心优势
- 零依赖：仅需本地 Git，无需沙箱/容器/虚拟机
- 超轻量：分支仅占几十字节，不占内存
- 高安全：沙箱隔离，main 永远稳定
- 超灵活：沙箱内权限全开，合并前严格把关
- 全语言通用：适配所有项目
- 本地优先：有无远程仓库都能用

## 快速开始
1. 本地初始化 Git 仓库（`git init`）
2. 导入 Claude 技能
3. 调用技能开始沙箱开发
