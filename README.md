# sandgit
轻量 Git 沙箱开发规范，专为 AI 辅助编程设计

## 核心理念
利用 Git 天然分支隔离能力，搭建极简代码开发沙箱。
将测试编写、业务开发拆分至独立沙箱分支，未通过审核、未通过校验的代码绝不合并入主分支，从底层守住项目稳定性，约束 AI 开发行为。

## 沙箱划分
1. 测试沙箱：`sgtest/*` 分支，仅用于编写、调试、确认测试框架
2. 业务沙箱：`sgcode/*` 分支，仅用于编写业务逻辑，禁止修改已定测试规则
3. 正式主干：`main` 唯一稳定上线分支

## 执行原则
1. 先搭建测试沙箱，确定需求校验标准，人工确认后再入库
2. 测试标准固化后，再开启业务沙箱开发
3. 业务代码必须全量通过已有测试框架才可审核
4. 沙箱内代码不合格直接废弃销毁，不污染主干代码

## 配套 Claude 技能
统一调用前缀，共6个技能，自由组合覆盖全部开发场景
- flow-sdd-base-sync  同步主干基线，初始化干净环境
- flow-sdd-test-branch-run  新建测试沙箱 + 编写测试 + 思路审核确认
- flow-sdd-test-finalize    测试沙箱合并 + 销毁沙箱分支
- flow-sdd-code-branch-run  新建业务沙箱 + 开发代码 + 效果审核确认
- flow-sdd-code-finalize    业务沙箱合并 + 销毁沙箱分支
- flow-sdd-branch-abort     一键废弃任意沙箱，快速回退主干

## 标准开发流程
1. 同步最新主干代码
2. 启动测试沙箱，完成测试编写与人审
3. 合并测试规则至主干，关闭测试沙箱
4. 再次同步主干最新代码
5. 启动业务沙箱，开发代码并通过全量测试
6. 业务审核通过后合并入库，销毁业务沙箱

## 异常处理
- 测试逻辑不符需求：沙箱内迭代修改，重新审核
- 代码无法通过测试：仅调整业务，不可篡改测试标准
- 需求变更/开发失败：直接废弃当前沙箱，重新拉起新沙箱
- 任务中途暂停：保留沙箱分支，后续接续开发

## 核心优势
- 零额外依赖：无需沙箱软件、容器、虚拟机，仅使用原生 Git
- 极致轻量化：分支仅占用极小存储，无内存溢出风险
- 强隔离安全：所有试验性代码隔离在沙箱，主干永久稳定
- 适配性广：不限编程语言，所有本地项目均可接入
- 管控性强：大幅提升 AI 生成代码贴合度，减少无效返工

## 快速接入
1. 导入配套 Claude 自定义技能
2. 在项目根目录配置简易规则文件
3. 直接调用技能开启沙箱化开发
